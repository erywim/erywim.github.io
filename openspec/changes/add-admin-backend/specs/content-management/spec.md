## Purpose

为所有会变动的博客内容提供 D1 工作区（草稿态）与显式的发布/同步流程：发布把 D1 内容生成文件提交进 Git 仓库触发站点重建，同步把仓库现状拉回 D1，GitHub 仓库始终是发布态数据的可靠归宿。

## ADDED Requirements

### Requirement: 九个内容域的工作区

系统 SHALL 为以下 9 个内容域提供 D1 内的创建、读取、更新、软删除能力，且在发布前不影响仓库与线上站点：冒险记录（blog）、旅行日志（logs）、篝火手记（chatter）、道具宝箱（treasure）、灵感火花（quest）、勇者档案（hero，单记录）、伙伴酒馆（friends）、大事记（timeline）、首页存档（party）。每条内容 SHALL 维护「相对仓库是否有未发布修改」的脏标记与「上次已知的仓库文件版本」标识。

#### Scenario: 新建草稿不触达线上
- **WHEN** 管理员在工作区新建一篇博客草稿
- **THEN** 草稿在后台列表可见且带脏标记，Git 仓库无变化，线上站点无变化

#### Scenario: 软删除暂不生效
- **WHEN** 管理员删除一个道具条目但未发布
- **THEN** 该条目标记为待删除，仓库文件仍在，站点仍展示

### Requirement: 条目发布（D1 → Git）

系统 SHALL 提供条目级发布：将内容渲染为对应的仓库文件（内容集合渲染为带 frontmatter 的 Markdown；hero/friends/timeline/party 渲染为完整 JSON 数据文件），通过 GitHub API 提交，成功后更新该条目记录的仓库文件标识、清除脏标记，提交触发既有 CI 构建使站点更新。发布前 SHALL 对内容做与站点构建 schema 一致的约束校验，违规数据拒绝发布并给出字段级错误。

#### Scenario: 发布已修改文章
- **WHEN** 管理员发布一篇修改过的文章
- **THEN** 仓库中对应 md 文件更新为最新内容（frontmatter 字段顺序稳定，diff 干净），条目脏标记清除，站点随后重建

#### Scenario: 违规数据拒绝发布
- **WHEN** 发布 rank 不在 S/A/B/C 或 gold 不在 1~19 的文章
- **THEN** 返回字段级校验错误，仓库无提交

#### Scenario: 发布软删除条目
- **WHEN** 管理员发布一个处于待删除状态的条目
- **THEN** 仓库对应文件被删除提交移除，条目从工作区清除

### Requirement: 全部发布

系统 SHALL 提供批量发布：按序发布所有脏条目；任一条目失败时停止后续并报告已完成与失败明细，失败不回滚已成功条目。

#### Scenario: 批量发布部分失败
- **WHEN** 3 条待发布，第 2 条校验失败
- **THEN** 第 1 条已提交生效，第 2、3 条未提交，结果中列出失败原因

### Requirement: 从仓库同步（Git → D1）

系统 SHALL 提供同步功能：读取仓库当前全部内容文件并导入/覆盖 D1 工作区，写入各条目的仓库文件标识、清除脏标记。首次播种 SHALL 复用同一逻辑完成存量内容初始化。

#### Scenario: 空库首次播种
- **WHEN** 在全新 D1 上执行同步
- **THEN** 仓库全部既有内容出现在工作区，全部无脏标记，字段与 frontmatter 一致

### Requirement: 仓库手改冲突检测

系统 SHALL 在打开编辑或同步时检测「仓库文件版本与上次已知版本不一致」（即仓库被后台之外的手改）。检出冲突时 SHALL 提示管理员二选一：以仓库覆盖本地（丢弃工作区修改），或以工作区强制发布（覆盖仓库手改），不得静默合并。

#### Scenario: 手改后打开条目
- **WHEN** 管理员本地直接改了 md 文件后，在后台打开同一条目
- **THEN** 显示冲突提示与两个选择，未选择前不发生任何写入

### Requirement: 图片上传进仓库

系统 SHALL 支持后台图片上传：图片经校验（类型与大小上限）后以二进制形式提交进仓库既定资产路径，返回可用于博客头图等字段的引用路径。上传遵循与内容发布一致的鉴权与审计。

#### Scenario: 上传合法图片
- **WHEN** 管理员在文章编辑器上传不超过上限的 PNG
- **THEN** 图片提交进仓库并返回引用路径，可被头图字段使用

#### Scenario: 超限或类型不符
- **WHEN** 上传超过大小上限或非图片类型的文件
- **THEN** 拒绝上传并返回原因，仓库无提交

### Requirement: 整文件 JSON 域的完整性

hero/friends/timeline/party 四个域 SHALL 以整文件方式发布：从 D1 全量重生成对应 JSON 文件，保序（如 friends 展示顺序、timeline 最新在前）。

#### Scenario: 调整伙伴顺序后发布
- **WHEN** 管理员在后台调整友链顺序并发布
- **THEN** 仓库 friends.json 完整反映新顺序，站点重建后展示一致
